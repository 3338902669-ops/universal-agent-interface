## 1. 项目摘要

本项目用一个窄范围原型检验：在 AI 生成代码的交付验收中，把任务要求、执行方声明、原始产物、可观察运行证据、核验者隔离情况和最终裁定绑定起来，能否减少错误通过，并让人更快定位失败原因。

本项目不是通用多 agent 平台，也不预设 UAI 已有独有创新或付费需求。先验证协议是否能在受控任务中产生可复核、可重放的裁定，再决定是否投入生产化和客户试点。

## 2. 事实、推断与待验证假设

### 已核实事实

- UAI 已有 protocol/unified/evidence-record.schema.json，包含任务、证据等级、声明者、命令/退出码/修订号、载荷 URI/哈希/字节数/媒体类型、读取者等字段。
- protocol/NOT-GUARANTEED.md 明确说明：哈希与日志不能证明命令真实执行；执行环境侧可验证证明尚未实现。
- stage2/three_layer_verdict.py 当前以 verifier 与 implementer 的 agent ID 不同作为独立性判断的一部分；不同 ID 本身不证明身份、信息隔离或错误独立。
- 当前仓库工作树已有未提交变更。本试点会新增隔离目录，不覆盖这些变更。
- 查阅的商业计划草案将收入、成本和客户转化数字列为未经合同验证的预测，不作为本试点市场需求证据。

### 推断

若裁定记录能绑定冻结后的证据包，并让第三方在不接触执行者解释的条件下重算，可能降低追查“做了什么、凭什么通过”的人工时间。

### 待验证假设

1. 证据完整性门槛能降低已知缺陷被错误接受的比例。
2. 身份、盲审、环境隔离和共享依赖记录，比“不同 agent ID”更能解释核验者间的错误相关性。
3. 结构化裁定记录能降低人工复核时间和故障归因成本。
4. 有团队愿意为上述改善提供试点数据或付费。当前没有合同或付费客户证据支持该项。

## 3. 目标与不做事项

### 目标

- 复用现有证据记录、裁定词表与事件账本，不重复建设通用任务编排。
- 实现一个可离线复算的代码交付证据包原型。
- 首轮只测离线包完整度、固定结构缺陷误接受、有效夹具误拒、合成根因归类与字段级复算一致性；真实语义错误率、人工复核时间、复核成本和核验错误相关性均留待后续。
- 明确每类证据能证明和不能证明的事项。

### 不做

- 不改生产 Hub、运行席位配置或凭据。
- 不实现多 Hub 高可用、通用沙箱、完整跨组织身份联邦或通用 agent 市场。
- 不把文件哈希解释成真实性证明，不把多厂商或多席位直接称为统计独立。
- 不开展客户外联，不作价格或收入承诺，不部署、不合并到默认分支。

## 5. 试验设计

首轮是**离线协议一致性试验**，不是对 agent 判断能力或市场需求的统计验证。只使用无凭据、无外部副作用的合成代码交付包，测试 UAI 能否把证据绑定起来、拒绝结构错误，并从完整证据包离线复算裁定。

建立 120 个固定夹具：40 个有效包、40 个已明确裁定为“不通过”的声明包、40 个证据缺陷包。声明不通过组只检验裁定/接受标记一致性，不代表检出了真实实质缺陷，也不用于估计语义错误率；证据缺陷组覆盖过期、错任务、错修订、哈希不符、路径越界、自我核验和产物篡改。测试 oracle 由夹具生成规则定义，属于合成测试标签，不称为人工金标准或真实世界标签。

每个包包含完整任务契约快照、符合 Evidence Record v1 的 evidence_records、冻结的产物字节与 manifest、执行声明、观察记录、核验记录和裁定。每条 evidence record 必须符合既有 schema；外层 profile 用固定相对 `$ref` `../../protocol/unified/evidence-record.schema.json`，空 registry 离线解析，不复制或改写 v1。task_id 在 packet/contract/每条 v1 record 一致；run_id/contract_id 留在 packet、claim、verifier 层；record.payload.uri 必须等于 manifest 对应 bundle-relative path，摘要和字节数与 manifest/字节一致；revision 按现有字段交叉核对，缺项判 unknown。复算单元为冻结仓库规则与 bundle，不声称 bundle 单独包含规则源。产物路径采用 NFC POSIX 相对语法；拒绝网络 URI、绝对路径、UNC、反斜杠、盘符、路径穿越、重复路径、符号链接/junction/硬链接逃逸和 shell 执行。过期按固定 `bundle.as_of` 与 `evidence_max_age_seconds` 计算，转为未核。

首轮不调用付费模型 API，不让 reviewer 对 120 个样本作主观判断。因此它可以检验格式、绑定、离线复算和确定性拒绝逻辑，**不能**检验语义错误通过、语义误拒、真实人工复核时间、跨厂商 verifier 独立性或付费意愿。上述项目列入后续盲审试点，需另行定义抽样、双核验者分配、顺序随机化、人工计时和费用口径；不得把席位 ID 或厂商差异单独当成独立性证明。

## 6. 指标与暂定门槛

首轮只对离线协议机制设门槛，语义表现与商业价值不作结论：

- 包完整度：所有被接受的样本均包含完整契约快照、v1 证据记录、产物字节和裁定引用；合成夹具目标 100%。
- 结构错误误接受：固定缺陷夹具被确定性校验器接受的数量；目标为 0。只表示固定测试集结果，不推断总体错误通过率。
- 有效包误拒：有效夹具被拒绝的数量；报告精确计数和区间，不将小样本差异宣传成普遍误拒率。
- 离线复算：相同冻结包与规则版本产生相同 canonical 输出；目标 100% 字段一致。采用试验内 `UAI-CJSON-v1`（UTF-8、键按 Unicode code point 排序、无空白、整数为主、拒绝浮点/重复键、字符串 NFC），并明确它不是 RFC 8785 实现；manifest 按 path 排序。packet digest 逐字段覆盖契约、records、manifest、execution_claim、runtime_observation、reviewer_record、adjudication_input 与 rules_version，追加事件通过 prev_digest 链接以避免自引用。改变任一覆盖字段后摘要必须变化。
- 失败归因：对预先定义的格式错误根因输出混淆矩阵；每类样本少于 10 时不报告宏平均 F1。
- 核验者共同漏检/错误相关性、语义错误通过率、语义误拒率、人工复核时间、review 成本：本轮不测，报告中必须标为“未测”，不能填 0。
- 运行耗时和本地计算量可作为实验描述记录；若未调用模型，模型费用记为“不适用”，不能外推未来单位成本。
- 固定样本比例报告分子、分母和 Wilson 95% 区间；这些区间只描述该合成样本，不能支持“总体错误率低于某阈值”的保证。

## 7. 阶段、投入与决策点

| 阶段 | 时间 | 主要工作 | 粗估投入 | 退出门 |
|---|---:|---|---:|---|
| 0. 计划与契约冻结 | 第 1 周 | 关闭 Evidence Record v1 映射、包自包含、裁定映射和安全路径约束；DSH 只读评阅 | 0.5–1 人周 | 所有阻断性契约问题均已解决；仅登记问题不能通过阶段门 |
| 1. 离线原型 | 第 1–2 周 | 外层 packet profile、纯函数校验器、冻结字节包、离线复算和故障夹具 | 1–2 人周 | v1 records 全部通过既有 schema；包离线可复算；无 shell/网络/包根外读取 |
| 2. 固定样本评测 | 第 2–3 周 | 对 120 个合成夹具运行正例、缺陷、篡改、错绑和重放矩阵 | 1–2 人周 | 断言、分子/分母、失败日志和报告可由原始样本复现 |
| 3. 独立核验与决策 | 第 4 周 | 天枢按冻结 commit 独立复算；Codex 提交 go/no-go 建议，用户决定是否进入真实 verifier 试点 | 0.5–1 人周 | 独立证据与自检分开；未测指标明确列出 |

**Go/no-go 门槛：**只有阶段 1/2 硬门全部通过、天枢提供可复现回执（命令、退出码、输入/输出 hash、复现说明）、未关闭阻断清单为零且所有未测指标仍标为 null/not_measured，才能提交 go 建议。天枢回执缺失或受阻时结论只能为 pending/no-go；Codex 自检不替代独立核验。

合计粗估 2.5–5 人周，为可用 agent 时间折算的规划数，不是供应商报价、获批预算或已验证商业成本。首轮不调用付费模型 API。真实 verifier 比较、人工计时和客户验证属于下一阶段，不能由本轮自动升级。

## 8. 风险和停止条件

- 真实性风险：执行声明可能为假；本轮不实现执行 attestation，不声称命令真实运行已获证明。
- 篡改边界：哈希检查能发现当前包内容与其摘要不一致；本地管理员可同时改包和摘要。本轮测试不宣称抵御拥有存储权限的恶意管理员。
- 样本偏差：合成 oracle 只检验程序是否满足预先写定的规则，不代表真实软件缺陷分布或人类验收质量。
- 相关错误风险：本轮没有两个语义 reviewer 的配对判断，故不测 reviewer 独立性或错误相关性。
- 误拒风险：过严的结构门槛可能阻断有效交付；有效夹具和缺证据夹具分别报告。
- 商业风险：未访谈客户、未验证预算；技术门槛通过不代表市场成立。
- 停止条件：Evidence Record v1 无法兼容复用；完整冻结包无法在离线环境复算；缺陷包可通过确定性门禁；有效包误拒无法解释；试验结果不能由他人从原始夹具复算。语义可靠性和商业投入决策留待下一阶段证据。

## 9. 后续商业验证

技术试点通过后，再选择一个使用 AI 编码 agent 的小团队，取得授权的脱敏任务样本，比较现行流程和证据包流程，并询问是否愿为节省的复核时间、审计能力或降低的交付风险付费。只有访谈记录、试用行为、预算承诺或合同才升级为需求证据。营业额预测继续标为假设，直至有客户证据。
