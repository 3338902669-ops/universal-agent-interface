# 不保证清单（NOT-GUARANTEED）

对应待完善项 **A-08**。本文件是 `contract-v1.md` 的**限定性附录**：契约正文规定"必须做到什么"，本文件规定"**没有承诺做什么**"。

两者不冲突；冲突时以本文件的不保证范围为准（即：不得把正文的任何条款解释成本文件列出的保证）。

> 写作原则：**明写比藏着强**。一份不写边界的规范，会被读者默认成"全都保证"。

---

## N1 不保证 exactly-once 执行

- 语义是「**至少一次投递 + 幂等键去重 + 租约围栏**」，不是「恰好一次执行」。
- 存在窗口：**执行成功、落账确认之前进程崩溃**。此时外部副作用已发生，账本无记录。
- 该窗口下的正确处置是：进入 `unknown` 操作账状态，**由核验者或负责人确认实际副作用后才能重试**，不得自动重放。
- 已实现支撑：操作账 `intent → confirmed / failed / unknown` 三态（契约 §9）。

## N2 不保证中枢高可用

- 当前**没有多 Hub 协调设计**（待完善项 A-09）。
- 两个中枢同时运行会导致**同一任务被派发两次**；围栏只能防旧结果写入，不能防双派发。
- 部署时必须保证同一命名空间内单中枢。

## N3 不保证审批人的真实身份

- 审批凭据里的 `approver_authenticity` 目前只能是 `asserted`（待完善项 A-01/C-03）。
- Orchestera 的 A4「审批人身份已认证」在 `conformance.json` 中状态为 **OUT OF SCOPE**；`governed-agent-runtime` 的 **F-GAR-08** 登记同一项。
- 消费者**必须**读该字段，不得把 `asserted` 当已认证。

## N4 不保证证据里的命令真的执行过

- E1 能证明"有人这样断言，并给出了命令、退出码、修订号"。
- 不能证明该命令在诚实环境中真的运行过；Orchestra 的 **E6** 为此状态 **OUT OF SCOPE**（待完善项 C-06）。
- 需要该保证时，必须引入执行环境侧的可验证执行记录（未实现）。

## N5 不保证进程内状态是安全边界

- 会话、grant、审批、账本目前都在进程内存 + 本地文件。
- 能在同一进程执行任意代码的 Agent **不受**这些机制约束（`governed-agent-runtime` **F-GAR-03**，按设计接受）。
- 对"不配合的 Agent"的强制，需要签名状态或外部授权服务（未实现）。

## N6 不保证跨厂商互操作已闭环

- 当前 A2A 边界是**只读投影**：对外可出 AgentCard / Task / 事件；**入站只到信封，未投递中枢**（待完善项 A-02）。
- 未实现 A2A streaming 与 push notification（A-04）。
- **没有跨域身份**，因此"不同厂商之间互信"这一前提尚不成立（A-01）。

## N7 不保证跨语言/跨实现的可移植性

- 参考实现是 Python + NATS；契约是语言无关的，但只有一份实现被验收过。
- 第二份独立实现（`adapters/verification-seat/`）已通过 6/6 契约边界检查，但同一作者编写，**不算独立实现**。
