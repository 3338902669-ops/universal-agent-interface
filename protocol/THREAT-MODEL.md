# 威胁模型（THREAT-MODEL v1）

对应待完善项 **A-10**。此前契约正文没有任何威胁模型章节，安全设计无法被系统检验。

---

## 1 资产

| 资产 | 位置 | 被破坏的后果 |
|---|---|---|
| 任务账本 | `data/ledger.jsonl`（追加式） | 事实源被改写 → 历史不可信 |
| 裁定记录 | `VERDICT` 条目 | 伪证被洗成通过 |
| 产物 | 指针 + sha256 | 交付物被替换而无人发现 |
| 租约/围栏 | 中枢内存 + 账本 | 两个执行者同时写同一任务 |
| 审批凭据 | 一次性、绑定 `action_digest` | 未授权的外部动作被执行 |
| 接口 token | 哈希存储 | 席位被冒充 |

## 2 信任边界

```text
   [负责人]  ── 审批 ──▶ [中枢 Hub]  ── 派发 ──▶ [接口 Interface] ──▶ [Runtime]
                              │                      │
                              ▼                      ▼
                          [账本 ledger]          [操作账 operations]
```

四条边界：
1. **负责人 → 中枢**：审批凭据是否真实、是否被重放
2. **中枢 → 接口**：派发是否被冒充、是否旧围栏
3. **接口 → Runtime**：Runtime 是否真的执行了它声称的事
4. **中枢自身**：中枢被攻破后，还有没有第二道闸

## 3 攻击者与假设

| 编号 | 攻击者 | 能力 | 是否在范围内 |
|---|---|---|---|
| T1 | **不诚实的执行席位** | 能自由构造它发给中枢的一切消息 | ✅ 核心范围 |
| T2 | **不诚实的核验席位** | 能签发自认为"通过"的裁定 | ✅ |
| T3 | **外部 A2A 客户端** | 能发任意入站请求 | ✅ |
| T4 | **同进程内的任意代码** | 能读写内存与本地文件 | ⚠️ **不在范围**（GAR F-GAR-03） |
| T5 | **中枢进程被完全接管** | 能改账本、伪造裁定 | ⚠️ **仅检测，不防御** |

**必须先明确**：T4/T5 不在防御范围，只能靠签名状态或外部授权服务。任何声称"能防内部人"的说法都超出本模型。

## 4 威胁与缓解现状

| 威胁 | 攻击路径 | 现有缓解 | 状态 |
|---|---|---|---|
| **S1 伪报完成** | 执行席位发 `completed` 而不附证据 | 裁定与执行分离；无证据不得判通过；六值 canonical | **已实现**（`projection.py` / `unified.py`） |
| **S2 伪造证据** | 附一份假产物的 sha256 | 中枢回读：存在性、字节数、媒体类型、哈希四校验 | **已实现**（契约 §8） |
| **S3 旧围栏污染** | 改派后旧执行者迟到提交 | `fence` 严格递增，旧围栏一律拒绝并留 `fencing_stale` | **已实现**（`reassign.py`，13/13） |
| **S4 重复派发** | 两个中枢各自派同一任务 | 中枢单例守卫：TTL + 心跳 + 接管留痕，无写权拒绝派发 | **已实现**（`hub_singleton.py`，13/13） |
| **S5 重放审批** | 复用旧凭据做第二次外部动作 | 凭据一次性 + 绑定 `action_digest`（去掉 approval 字段的摘要） | **已实现**（`unified.py`） |
| **S6 审批人冒充** | 声称"某人批过了" | `approver_authenticity` 默认 `asserted`，**无验证器不得升级** | **部分**（`identity.py` 只到接口，未接 IdP） |
| **S7 席位冒充** | 用别人的 interface_id 注册 | token 哈希 + HMAC 常量时间比较 | **已实现**（单域） |
| **S8 账本篡改** | 直接改 `ledger.jsonl` | 无哈希链（GAR 有，UAI 无） | **缺口** |
| **S9 中枢被攻破** | 有 root 权限改一切 | 仅能事后审计 | **超出范围** |
| **S10 证据里的命令未真跑** | 编造 command/exit_code | 无法证明 | **OUT OF SCOPE**（AO 的 E6） |

## 5 四个信任问题不可互相顶替

| 问题 | 机制 | 能防住 | 防不住 |
|---|---|---|---|
| 接口认证 | token + HMAC | 席位冒充（S7） | 合法席位说假话（S1） |
| 操作授权 | grant（单次/过期/绑定目标） | 越权执行 | 授权范围内的伪造结果 |
| 执行可信 | 操作账 intent→confirmed/unknown | 无声副作用 | 有意的假记录 |
| 结果可信 | 核验者≠实现者 + 六值裁定 | 伪报完成（S1/S2） | 核验者与被验者合谋 |

**合谋（S1+T2 联手）不在本模型范围内**——只能靠人的抽样与外部审计。

## 6 已知缺口（与架构 TODO 对应）

| 缺口 | 对应项 | 影响 |
|---|---|---|
| 账本无哈希链 | 新增（本文件 S8） | 篡改只能靠文件系统审计发现 |
| 审批人身份只到 `asserted` | A-01 / C-03 | 审批可伪造（S6） |
| 中枢单例是单机文件锁 | A-09 | 跨机部署需换 etcd/Consul，语义不变 |
| 无多方裁定与申诉 | 门槛 4 | 跨厂商争议无法裁决 |
| 同进程代码不在防御范围 | T4 / GAR F-GAR-03 | 只能靠外部授权服务 |

## 7 复核要求

- 每次新增对外入口（入站、SSE、webhook）必须更新 §4 表格
- 每次解除一条缺口，必须在 §6 留下关闭记录（日期 + 证据 + 核验者）
- 本文件由未参与实现的席位复核；实现者自评不计
